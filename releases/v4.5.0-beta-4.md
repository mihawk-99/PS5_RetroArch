# PS5_RetroArch-v4.5.0-beta-4

**Eleven community pull requests in one release, and zipped games start from EmulationStation.**

<img src="https://raw.githubusercontent.com/mihawk-99/PS5_RetroArch/main/assets/readme/important-warning.png" alt="Important warning">

## PS5 RetroArch is a passion project, not a piracy project.

It exists so you can play the games you own on the console you own.

- **Piracy is not condoned.**
- **No games, BIOS files, console firmware or decryption keys are included, and they never will be.**
- **Use only legally obtained backups of games you own**, made yourself from your own discs, cartridges or digital purchases.
- **Use only BIOS and firmware files dumped from hardware you own.**
- **Requests for, or links to, games, BIOS files, firmware or keys are not welcome** in this project's issues or discussions.

<a id="zipped"></a>

## <img src="https://raw.githubusercontent.com/mihawk-99/PS5_RetroArch/main/webui/assets/fluent/library.svg" width="26" height="26" alt=""> Zipped games in EmulationStation

- **A zipped game now starts.** RetroArch's scan lists a game inside an archive as `Game.zip#Game.sfc` when the core does not open archives itself. EmulationStation showed that game, and starting it was refused because that name is not a file on its own.
- **It is listed once.** A zipped game that was both in a playlist and in a content folder appeared twice, in EmulationStation and in the WebUI.
- **Two games in one archive stay two games** in RetroArch and the WebUI. EmulationStation lists files, so it shows that archive once.

<a id="faster"></a>

## <img src="https://raw.githubusercontent.com/mihawk-99/PS5_RetroArch/main/webui/assets/fluent/arrow-sync.svg" width="26" height="26" alt=""> A faster EmulationStation

- **Less work at every start** ([#112](https://github.com/mihawk-99/PS5_RetroArch/pull/112)). Reading the library no longer compares every game with every other one, game lists are rewritten only when they changed, and theme files are read once while it starts. Nothing is kept between runs, so nothing can go stale.
- **No rescan after a game** ([#99](https://github.com/mihawk-99/PS5_RetroArch/pull/99)). Back from a game, EmulationStation keeps the lists it had and adds that play itself. A game added meanwhile through the WebUI shows the next time EmulationStation is started from the picker or the home screen.

<a id="separate"></a>

## <img src="https://raw.githubusercontent.com/mihawk-99/PS5_RetroArch/main/webui/assets/fluent/content-view.svg" width="26" height="26" alt=""> Separate systems

- **One system per playlist, if you want it** ([#105](https://github.com/mihawk-99/PS5_RetroArch/pull/105)). In the WebUI: Settings → Interface → **Separate ES-DE systems by playlist**. It is off by default and applies the next time EmulationStation starts.
- **What it does.** A system fed by more than one playlist or content folder becomes one EmulationStation system for each, with the same theme and core. A system with a single source stays exactly as it is.
- **Artwork.** A split system looks for its artwork in a folder of its own name, so artwork the WebUI stored for the combined system does not follow it.

<a id="startup"></a>

## <img src="https://raw.githubusercontent.com/mihawk-99/PS5_RetroArch/main/webui/assets/fluent/home.svg" width="26" height="26" alt=""> Startup and online features

- **"Startup refused" on newer firmware** ([#49](https://github.com/mihawk-99/PS5_RetroArch/pull/49), [#60](https://github.com/mihawk-99/PS5_RetroArch/pull/60), [#59](https://github.com/mihawk-99/PS5_RetroArch/issues/59)). The title looked for its own folder in three fixed places. It now also finds a sandbox folder with any number, and recognises its executable through a mount that reports a device of its own. It still never takes another copy of the title for itself.
- **Online features on a USB install** ([#98](https://github.com/mihawk-99/PS5_RetroArch/pull/98), [#96](https://github.com/mihawk-99/PS5_RetroArch/issues/96)). The Lapy service wrote its "ready" file to the internal folder while the title looked beside itself, so a title on a USB drive stayed offline. The service now writes beside the mounted title.
- **Not confirmed on the affected setups.** These were built for firmware 13.60 and USB installs, which could not be tested here; a normal install on firmware 6.02 starts as before. If you were affected, please say whether this release fixes it.

<a id="helper"></a>

## <img src="https://raw.githubusercontent.com/mihawk-99/PS5_RetroArch/main/webui/assets/fluent/laptop.svg" width="26" height="26" alt=""> PC media helper

- **Works for a console with no internet** ([#117](https://github.com/mihawk-99/PS5_RetroArch/pull/117)). In PC mode the console still asked the internet itself whether an image exists, for the folder listings and for the LaunchBox database. The helper on your PC now answers all of those, for the libretro and LaunchBox sources. ScreenScraper stays console-only, so its account never leaves the console.
- **Fixed on the way in:** a name search could hang the WebUI while a job waited for the helper, and a slow download could be started twice and corrupt its file.
- **Use the helper from this package** (`webui/ps5-media-helper.py`): an older copy does not answer the new questions.

<a id="smb"></a>

## <img src="https://raw.githubusercontent.com/mihawk-99/PS5_RetroArch/main/webui/assets/fluent/cloud.svg" width="26" height="26" alt=""> Artwork from an SMB share

- **Experimental** ([#113](https://github.com/mihawk-99/PS5_RetroArch/pull/113)). With a server saved in the WebUI's SMB page, RetroArch playlists of `smb://` games and a catalogue file you write yourself (`es-de/ES-DE/smb-catalog.xml`), EmulationStation lists those games, shows covers from the share as you scroll and plays video previews from it. Nothing is cached on the console.
- **Off unless all three are there**, and not yet run on a console with a real share. No tool writes the catalogue yet. With the server switched off, EmulationStation can pause for a few seconds when it reaches for it.

<a id="cores"></a>

## <img src="https://raw.githubusercontent.com/mihawk-99/PS5_RetroArch/main/webui/assets/fluent/settings.svg" width="26" height="26" alt=""> Cores

- **Opera (3DO)** ([#102](https://github.com/mihawk-99/PS5_RetroArch/pull/102)): upstream's fix for opening movies that stalled, and its new default CD speed of 2x, the real drive's. A speed you chose yourself is kept.
- **For core developers** ([#114](https://github.com/mihawk-99/PS5_RetroArch/pull/114)): a core can ask whether hardcore mode is on, ask for the savestate folder, and play sound on each controller's speaker. No core in this package uses them yet.
- **Amstrad CPC** ([#72](https://github.com/mihawk-99/PS5_RetroArch/pull/72)): the core builds, from its own fork [PS5_Cap32](https://github.com/mihawk-99/PS5_Cap32), and ran on a Base PS5. It is **not in this package**: it carries Amstrad's system ROMs inside the core, and this project ships no console firmware.

<a id="upgrading"></a>

## <img src="https://raw.githubusercontent.com/mihawk-99/PS5_RetroArch/main/webui/assets/fluent/arrow-sync.svg" width="26" height="26" alt=""> Upgrading from v4.4.0-beta-4

1. **Back up your existing title folder**, especially configuration, saves, states, system files, content and any custom media.
2. **Use the WebUI's Update button**, or merge the complete `PPSA99169` folder from the package into your installation, keeping your own files and configuration.
3. Fully close and reopen PS5 RetroArch. The new Lapy service starts after the next console restart; until then the one already running keeps working.

**No games, BIOS files, console firmware, or decryption keys are supplied. Use only legally obtained backups of games you own and system files dumped from hardware you own.**
